# Requisitos Funcionales

* **RF-01 Gestión de Plantillas Clínicas:** El sistema debe proveer los formatos estandarizados e independientes para hospitalización, hemodiálisis, consulta externa, quirófano y cuidados intensivos (neonatales, pediátricos y adultos), aplicando las reglas de llenado de la guía operativa 39.[cite: 151]
* **RF-02 Gestión MultiPaciente y Navegación:** El sistema debe permitir al profesional de enfermería gestionar simultáneamente la información de varios pacientes o camas, organizando el acceso mediante un sistema de pestañas.[cite: 151]
* **RF-03 Accesibilidad Contextual a Escalas:** El sistema debe proporcionar acceso directo a las herramientas de valoración clínica exactamente en las secciones correspondientes de la hoja de enfermería.[cite: 151]
* **RF-04 Controles de Selección Rápida:** El sistema debe limitar la entrada de texto libre en campos predefinidos, obligando al usuario a presionar botones o seleccionar opciones preconfiguradas para escalas clínicas (Glasgow, EVA, Flebitis Maddox, Downton, Bristol).[cite: 151]
* **RF-05 Validación de Valores Clínicos:** El sistema debe incluir reglas de validación lógica de entrada de datos (alertas o límites numéricos) al capturar constantes vitales como presión arterial, temperatura, balances de líquidos y puntajes de escalas.[cite: 151]
* **RF-06 Generación de Gráficas Automáticas:** El sistema debe trazar automáticamente las gráficas clínicas de signos vitales (temperatura, tensión arterial, etc.) exigidas por la guía operativa 39 a partir de los datos ingresados.[cite: 151]
* **RF-07 Generación e Impresión de Hojas de enfermería (PDF):** El sistema debe imprimir el registro realizado con el formato de la plantilla de las hojas de enfermería planteadas de manera alámbrica e inalámbrica por bluetooth (En caso de que la impresora tenga conexión por bluetooth).[cite: 151]
* **RF-08 Autenticación en Línea:** El sistema debe permitir un inicio de sesión rápido validando la identidad del profesional a través de su cédula profesional, siendo esta la única función que obligue al uso de internet.[cite: 151]
* **RF-09 Verificación Biométrica/PIN de Sesión:** El sistema debe mantener la sesión activa en segundo plano, pero exigirá un factor de verificación local (huella dactilar o PIN) cada vez que la aplicación pase a primer plano.[cite: 151]
* **RF-10 Gestión de Firma Digital:** El sistema debe permitir al enfermero adjuntar, guardar y administrar una firma digital vinculada exclusivamente a su perfil de usuario.[cite: 151]
* **RF-11 Inserción Rápida de Firma:** El sistema debe habilitar un botón de acción rápida que inserte automáticamente la firma del perfil del usuario en las áreas de validación o cierre de turnos.[cite: 151]
* **RF-12 Transferencia Vía QR/Bluetooth (Lotes):** El sistema debe generar códigos QR para emparejar dispositivos y compartir expedientes de pacientes en lotes de 1 hasta 10 pacientes simultáneos mediante conexión Bluetooth local.[cite: 151]
* **RF-13 Confirmación de Doble Factor en Transferencias:** El sistema debe requerir una confirmación de dos pasos entre el emisor y el receptor antes de ejecutar la transferencia vía QR/Bluetooth, garantizando que no haya pérdida de datos.[cite: 151]
* **RF-14 Autenticación y Generación de Token:** El dispositivo debe utilizar internet únicamente al inicio del turno. Se enviarán las credenciales al servidor de validación y, si son correctas, el servidor responderá con un Token criptográfico (como un JWT - JSON Web Token) que contiene los permisos del usuario y una fecha de expiración definida de un mes. Este token se almacenará en el área segura del dispositivo.[cite: 151]
* **RF-15 Validación Local Continua:** El sistema debe permitir que, una vez guardado el token, el dispositivo se desconecte por completo de la red. Cuando el enfermero bloquee el teléfono o minimice la aplicación, el sistema de seguridad (PIN o Huella Dactilar) operará verificando la credencial contra el token almacenado localmente, sin hacer llamadas a internet extendiendo su sesión fuera de línea un mes.[cite: 151]
* **RF-16 Transferencia P2P (Peer-to-Peer):** El sistema debe ejecutar el intercambio de expedientes entre enfermeros al cambiar de turno mediante protocolos de proximidad (Bluetooth Low Energy o Wi-Fi Direct), utilizando el código QR exclusivamente para establecer el "apretón de manos" seguro entre los dos dispositivos físicos.[cite: 151]
* **RF-17 Cálculo Automático de Fórmulas:** El sistema debe calcular automáticamente el Índice de Masa Corporal (IMC), Superficie Corporal, Presión Arterial Media y balances de control de líquidos (ingresos/egresos totales) sin requerir cálculos mentales del usuario.[cite: 151]
* **RF-18 Inserción Automatizada de Firma con Datos de Identificación:** El sistema debe permitir al usuario validar las secciones que requieren firma (incluyendo los apartados de doble verificación) presionando un único botón de acción en la interfaz gráfica. Al compilar y generar la hoja de enfermería, el sistema debe plasmar automáticamente la firma digital vinculada a la sesión y, justo debajo de esta, insertar el nombre completo y el número de cédula profesional del usuario en un tamaño de fuente reducido, respetando los espacios del formato oficial.[cite: 151]
* **RF-19 Gestión de Personal y Cédulas (Panel Web):** El sistema debe contar con un módulo administrativo (separado de la aplicación móvil) donde un usuario con rol de Administrador pueda dar de alta, modificar, suspender o eliminar las cédulas profesionales y datos del personal de enfermería autorizado.[cite: 151]
* **RF-20 Validación de Preautorización (Lista Blanca):** Durante la autenticación en línea (RF-14), el sistema debe rechazar cualquier intento de acceso desde la aplicación móvil si la cédula ingresada no se encuentra activa y pre-registrada en el panel administrativo.[cite: 151]
